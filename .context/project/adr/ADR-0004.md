# ADR-0004: Contrato del endpoint de liveness

## Estado

Aceptada

## Contexto

El endpoint de liveness debe permitir a un consumidor externo comprobar que el proceso PHP y la ruta HTTP de Moodle pueden responder. No debe expresar la disponibilidad de las dependencias de la aplicación.

## Decisión

El endpoint será `GET /api/rest/v2/local_health/live`.

Cuando la ruta se complete correctamente, responderá:

```http
200 OK
Content-Type: application/json
Cache-Control: no-store
```

```json
{"status":"UP"}
```

La ruta no aceptará parámetros, no requerirá autenticación, no utilizará cookies ni iniciará una sesión. Se declarará con `cookies: false` y `abortafterconfig: true` para evitar cargar el stack completo de Moodle.

No ejecutará probes ni realizará comprobaciones intencionadas contra base de datos, caché, sistema de archivos o servicios externos. Los fallos de esas dependencias se evaluarán mediante `ready` o `health`.

## Consecuencias

- `200 OK` confirma únicamente la disponibilidad del proceso y de la ruta.
- El cuerpo es un contrato JSON mínimo y explícito.
- No se definirá una respuesta `503` de aplicación para `live`.
- Si Moodle no puede cargar su configuración o enrutar la solicitud, la respuesta de error queda a cargo del servidor o del framework.
